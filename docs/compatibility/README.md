## 常驻保护主验收

`protected-session-probe` 使用生产窗口服务与macOS原生适配器，独立NSPanel在第一次显示前设置默认捕获属性。整轮保持开启，初次采集结束后重新创建SCStream和包含过滤器，再采集同一个目标。两段各至少三十秒，期间没有调用切换属性的诊断入口。

## 已取得的本机证据

2026-11-08，在 macOS 27.0（26A428）、Apple Silicon 上运行 `node scripts/run.mjs panel-probe`。独立 AppKit NSPanel + WKWebView 加载本地合成页面，复用生产窗口应用服务和原生驱动。报告见 [原始 JSON](evidence/macos-27-panel-2026-11-08.json)。

- WKWebView 完成页面加载，面板显示后没有改变前台应用。
- 面板创建时设置 nonactivating 标记，明确拒绝成为 key/main window；直接请求 makeKeyWindow 后仍未取得键盘焦点。
- 两个重叠截图租约期间窗口透明度为零；第一个释放后仍保持零，最后一个释放后恢复一。
- 截图期间新建的第二窗口继承透明状态，最后恢复；关闭、注销和重新创建后重新应用策略。
- 八个窗口阶段的系统属性及焦点观察均通过。

这个原型没有捕获桌面、没有注入物理点击和按键、没有测试中文输入法，没有启动任何真实会议或笔试平台。`sharingType == none` 的读回只证明属性设置成功。

2026-11-09，在同一系统运行 `node scripts/run.mjs host-probe`。这是打包使用的固定补丁 Wails 2.12.0 宿主，复用生产 StateManager，使用独立合成页面，不加载真实配置或模型。报告见 [宿主 JSON](evidence/macos-27-host-2026-11-09.json)。

- 启动：实际窗口是 nonactivating NSPanel，拒绝 key window，前台应用保持不变。
- 显式编辑：生产接口开启焦点门后，应用成为前台、窗口成为 key，WebView 输入框获得焦点并完成中文字符串的桥接往返。
- 返回：关闭焦点门、放弃 key window，并恢复启动前的应用。

字符串由测试页面写入，没有经过物理键盘或中文输入法转换。该测试没有注入全局输入、捕获屏幕、打开真实账号或观察第三方网页事件。以上是这台 Mac 上的宿主证据，不能外推为 60 项平台兼容性通过。

补齐图像就绪等待与帧状态记录后，短时单窗口流的关闭/开启/关闭对照连续五轮通过。判定要求每阶段至少 3 个完整帧，时间戳严格递增且跨度至少 200 毫秒。缺帧、缺失基线、混入可见帧或流停止失败均不能判为隐藏成功。首次运行因输出色彩空间与图像解码设置不一致而被基线检查拒绝，统一为 sRGB 后完成对照。另一次复测虽然流启动成功，却没有提供完整图像帧，同样记为无法确定。两次失败记录均保留在本机。

### 同一视频流中的保护切换

随后运行 `live-capture-probe`，完成多窗口生命周期检查后关闭额外的测试窗口，按生产的单窗口形态保持一个 `SCStream` 和同一个过滤器持续运行。每阶段至少持续 2 秒，通过生产窗口服务切换捕获属性，全程启动、停止各一次，报告核对注册窗口数量为一。代表记录包含 94 个完整帧，全部原始 PNG 与时间线见 [连续流切换证据](evidence/macos-27-sck-live-2026-11-09/report.json)。

| 阶段 | 完整帧结果 | 本地窗口状态 |
| --- | --- | --- |
| 关闭保护的前基线 | 32 帧含红绿标记 | visible=true，alpha=1 |
| 中途开启 sharingType none | 31 帧均为 100% 透明，原始 RGB 全零 | visible=true，alpha=1 |
| 中途再次关闭保护 | 31 帧恢复红绿标记 | visible=true，alpha=1 |

单窗口形态下首轮与两轮复测均完成上述对照，每轮 94 个完整帧，保护阶段各 31 帧全部透明，原始采集缓冲内的 RGB 数据均为零。首个透明采样帧出现在属性确认后约 41 至 49 毫秒，采样频率为 15fps。这个数值表示下一张已观察帧的时间，实际生效时刻位于相邻帧之间。

时间线使用 CoreMedia host clock，WindowServer 的 displayTime 由同一时钟换算。画面生成时间与应用属性确认时间相互比较，收到较晚的旧帧仍归到它实际生成的阶段。所有完整帧都保留，有效时间线中保护阶段出现任何可见帧都会记录为 `visible` 或 `transition-leak`。原始 RGB 也单独检查，Alpha 透明但仍有颜色数据时记录为 `transparent-with-data`。采样不足、时钟不可比、窗口本地透明、缺失基线或流重启均使判定失败。[Apple displayTime](https://developer.apple.com/documentation/screencapturekit/scstreamframeinfo/displaytime)、[host time 换算](https://developer.apple.com/documentation/coremedia/cmclockmakehosttimefromsystemunits%28_%3A%29)。

早期保留双窗口的原型曾在关闭保护后先采到一帧透明内容，再恢复可见内容，该过渡与原始记录保留在本机。恢复阶段的完整帧均进入时间线，结束时要求连续三帧可见。当前三轮单窗口记录的恢复阶段均为 31 个可见帧。

该结果验证这台 Mac 上同一单窗口流中途切换属性的短时行为。长时运行、显示器捕获及真实会议共享接收端仍待验收，60 项平台矩阵维持原状态。

### 显示器包含窗口过滤器

新增 `display-capture-probe`，使用显示器的 `includingWindows` 过滤器，实际名单仅含自建测试窗口，音频关闭。采集前核对包含名单、窗口进程、显示器身份及精确裁剪范围。代表记录中显示器为1512×982点，窗口及裁剪区域均为390×170点。该过滤器限定选定窗口，桌面及 Dock 由系统排除。[Apple 包含窗口过滤器](https://developer.apple.com/documentation/screencapturekit/sccontentfilter/init%28display%3Aincluding%3A%29?language=objc)

首轮完整观察保存了62张真实新图像和93次系统输出。开启保护后有一张全透明、原始RGB全零的图像，随后30次 idle 持续保持该图像。再次关闭保护后，先收到一次保持透明图像的 idle，之后30张新图像恢复可见。窗口本地始终保持显示状态。[原始图像与完整输出时间线](evidence/macos-27-sck-display-window-2026-11-09/report.json)

| 阶段 | 新图像 | idle | 接收端观察 |
| --- | --- | --- | --- |
| 前基线 | 31 | 0 | 31次均可见 |
| 开启保护 | 1 | 30 | 31次均保持透明、原始RGB全零 |
| 关闭保护 | 30 | 1 | 一次透明过渡，随后30次可见 |

最初沿用单窗口的新帧规则时，显示器路径只有一张透明新图像，且部分呈现时间比接收回调晚数毫秒，被判为无法确定。之后补充了每次实际输出、引用的真实图像编号与接收时间。idle 表示没有产生新图像，检验以持续保留的上一张图像为观察内容。每阶段覆盖至少1.5秒，输出空缺最多250毫秒，缺失图像、缺失状态记录或只保持可见图像都不能判为隐藏成功。最初记录保留在本机。[Apple idle 状态](https://developer.apple.com/documentation/screencapturekit/scframestatus/idle)

随后复测时 Mac 进入锁屏及显示器休眠，活动显示器数量为零。两次显示器复测及一次原单窗口回归受到环境阻塞，保留了失败记录。新增的启动前环境检查已在锁屏状态确认快速退出，记录见 [环境阻塞](evidence/macos-27-sck-display-window-2026-11-09/environment-blocked.json)。用户解锁后完成下述复测。

### 采集开始前已开启保护

## 平台矩阵

[matrix.json](matrix.json) 当前有 60 个待测组合：macOS/Windows 各覆盖腾讯会议、飞书会议、钉钉会议、Zoom、Google Meet、Microsoft Teams、企业微信的整屏与单窗口共享；牛客、赛码、HackerRank、Codility 的屏幕共享、被动输出焦点、显式编辑焦点和键盘传播场景。

这些名称定义验证范围，不表示每个平台必定提供某种检测能力、共享模式或相同产品版本。入口不支持的场景应记录原因和证据，调整需求并重新审阅，不能随意填成通过。

每条已测记录必须有系统版本、平台客户端/浏览器版本、应用修订、时间和证据；共享结果还必须有独立接收端。证据只保留本地合成题面、自己的测试会议和受控窗口，避免记录账号、公司聊天或真实考试内容。记录共享选择是整屏、窗口还是其他来源；能够确认底层捕获 API 时再补充，无法确认时写明未知。

原生侧与网页侧至少联合观察：实际收到的按下/释放事件、快捷键执行次数、当前前台进程、key window、`document.hasFocus()`、`focus/blur`、`visibilitychange`、全屏状态以及独立接收画面。浏览器里的合成 `dispatchEvent` 不代表物理键盘路径；本机截图不代表会议远端画面。

`node scripts/compatibility.mjs` 只校验记录结构并统计缺口。`--require-complete` 要求全部组合有足够证据且结果符合该场景的预期；当前应失败，因为 60 项尚未执行。
