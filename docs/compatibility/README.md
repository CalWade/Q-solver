# 兼容性记录与验收

这里分别记录原生宿主证据和第三方平台的实际结果。未执行的组合保持 `not_run`，不得从系统属性、网页模拟测试、构建成功或其他产品宣传填成通过。

## 已取得的本机证据

2026-11-08，在 macOS 27.0（26A428）、Apple Silicon 上运行 `node scripts/run.mjs panel-probe`。独立 AppKit NSPanel + WKWebView 加载本地合成页面，复用生产窗口应用服务和原生驱动。报告见 [原始 JSON](evidence/macos-27-panel-2026-11-08.json)。

- WKWebView 完成页面加载，面板显示后没有改变前台应用。
- 面板创建时设置 nonactivating 标记，明确拒绝成为 key/main window；直接请求 makeKeyWindow 后仍未取得键盘焦点。
- 两个重叠截图租约期间窗口透明度为零；第一个释放后仍保持零，最后一个释放后恢复一。
- 截图期间新建的第二窗口继承透明状态，最后恢复；关闭、注销和重新创建后重新应用策略。
- 八个窗口阶段的系统属性及焦点观察均通过。

这个原型没有捕获桌面、没有注入物理点击和按键、没有测试中文输入法，没有启动任何真实会议或笔试平台。`sharingType == none` 的读回只证明属性设置成功。

2026-11-09，在同一系统运行 `node scripts/run.mjs host-probe`。这是打包使用的固定补丁 Wails 2.12.0 宿主，复用生产 StateManager，使用独立合成页面，不加载真实配置或模型。报告见 [宿主 JSON](evidence/macos-27-host-2026-11-09.json)。

- 启动：实际窗口是 nonactivating NSPanel，拒绝 key window，前台应用保持不变。
- 显式编辑：生产接口开启焦点门后，应用成为前台、窗口成为 key，WebView 输入框获得焦点并完成中文字符串的桥接往返。
- 返回：关闭焦点门、放弃 key window，并恢复启动前的应用。

字符串由测试页面写入，没有经过物理键盘或中文输入法转换。该测试没有注入全局输入、捕获屏幕、打开真实账号或观察第三方网页事件。以上是这台 Mac 上的宿主证据，不能外推为 60 项平台兼容性通过。

同日运行 `node scripts/run.mjs focus-probe`，使用独立临时 Chrome 156.0.8078.80 接收页面与真实宿主联合测试。显式关闭 Playwright 默认的焦点模拟。两个原生 E2E 通过，完整报告见 [联合证据](evidence/macos-27-chrome-focus-2026-11-09.json)。

| 阶段 | 外部页面 hasFocus | 实际事件 |
| --- | --- | --- |
| 启动被动面板 | true | 没有 blur |
| 显式进入编辑 | false | 收到可信 blur |
| 返回被动面板 | true | 收到可信 focus |

三个阶段 `visibilityState` 都是 `visible`，均不在全屏状态。这说明本次编辑会被页面失焦监听观察到；不能只看 `visibilitychange` 是否发生。第二个测试主动在编辑中断开观察器，验证原生进程以失败状态退出且浏览器重新获得焦点。

本项没有向第三方页面投递代码，也未使用物理鼠标/键盘、输入法或屏幕共享。它验证独立页面和当前 Chrome 的焦点路径，矩阵中各真实平台仍保持 `not_run`。

同日新增 `keyboard-probe`，独立 Chrome 156.0.8078.80、内部 WKWebView 与真实 macOS session event tap 联合验证。当前三项原生键盘 E2E 通过，原始数据见 [键盘联合报告](evidence/macos-27-keyboard-2026-11-09.json)。最初十组场景的两项 E2E 曾连续三轮共六次通过，随后加入残留编辑意图与前台切换终止用例。

| 场景 | 原生与接收端结果 |
| --- | --- |
| 左右侧关闭防护基线 | 接收端收到对应修饰键与主键 |
| 左侧防护 | 接收端收到后续普通按键，完整 Command+A 序列被拦截，动作执行一次 |
| 自动重复、先释放 Command | 动作仍执行一次，主键释放事件继续被拦截 |
| 只按未选中右侧 | 与右侧基线的完整事件记录相同 |
| 双侧同时按下 | 受保护侧优先，动作执行一次 |
| 不匹配诊断标记的事件 | 正常传递，与关闭防护的基线相同 |
| 再次关闭防护 | 与左侧基线相同 |
| 内部编辑 | WKWebView 收到组合键，合成文字被输入字母替换，动作执行零次 |
| 返回外部应用但编辑意图尚未清除 | 外部应用的键盘防护生效，动作执行一次 |
| 退出编辑 | 浏览器重新获得焦点，左侧防护和动作恢复 |
| 控制端断开 | 进程报告失败并退出，本进程系统监听数量恢复到初值 |
| 切换到另一个自有测试浏览器 | 投递前检查发现前台改变，测试终止，新浏览器未收到测试按键，监听被移除 |

事件由 CGEvent 软件接口产生，经过实际系统过滤与页面接收链路。诊断过滤器限定随机标记，普通物理输入走正常路径。物理键盘设备与中文输入法仍待独立验收。

重复运行中曾出现前台切换到 ChatGPT 的中断，诊断检查按预期终止，该次记录为失败。正向场景要求接收端持续保持前台，不能把桌面被其他应用打断后的退出计为通过。随后用另一个隔离浏览器主动重现前台切换，单独验证终止与清理路径。

同日在 macOS 27.0（26A428）运行 `capture-probe`，通过 `ScreenCaptureKit.SCScreenshotManager` + `desktopIndependentWindow` 捕获自建面板。只采集该窗口，不采集桌面或其他应用。三个连续样本见 [捕获报告](evidence/macos-27-sck-window-2026-11-09.json)。

| 捕获属性 | 实际图像 | 像素观察 |
| --- | --- | --- |
| 关闭保护 | [前基线](evidence/macos-27-sck-before.png)，390×170 | 红色占 46.84%，绿色占 49.35%，透明占 0% |
| sharingType none | [开启保护](evidence/macos-27-sck-protected.png)，195×85 | 红绿标记均为 0%，透明占 100% |
| 再次关闭保护 | [后基线](evidence/macos-27-sck-after.png)，390×170 | 与前基线相同，内容恢复 |

结果是该路径返回透明内容。窗口仍能在 `SCShareableContent` 中按 windowID 找到，不能解释为源列表不可枚举。本次也没有测试连续 `SCStream`、整屏捕获或会议远端；不能把“ScreenCaptureKit”当作只有一种固定结果的单一接口。三张图像都是合成测试内容，保留了原始字节，未做图像编辑。

## 平台矩阵

[matrix.json](matrix.json) 当前有 60 个待测组合：macOS/Windows 各覆盖腾讯会议、飞书会议、钉钉会议、Zoom、Google Meet、Microsoft Teams、企业微信的整屏与单窗口共享；牛客、赛码、HackerRank、Codility 的屏幕共享、被动输出焦点、显式编辑焦点和键盘传播场景。

这些名称定义验证范围，不表示每个平台必定提供某种检测能力、共享模式或相同产品版本。入口不支持的场景应记录原因和证据，调整需求并重新审阅，不能随意填成通过。

每条已测记录必须有系统版本、平台客户端/浏览器版本、应用修订、时间和证据；共享结果还必须有独立接收端。证据只保留本地合成题面、自己的测试会议和受控窗口，避免记录账号、公司聊天或真实考试内容。记录共享选择是整屏、窗口还是其他来源；能够确认底层捕获 API 时再补充，无法确认时写明未知。

原生侧与网页侧至少联合观察：实际收到的按下/释放事件、快捷键执行次数、当前前台进程、key window、`document.hasFocus()`、`focus/blur`、`visibilitychange`、全屏状态以及独立接收画面。浏览器里的合成 `dispatchEvent` 不代表物理键盘路径；本机截图不代表会议远端画面。

`node scripts/compatibility.mjs` 只校验记录结构并统计缺口。`--require-complete` 要求全部组合有足够证据且结果符合该场景的预期；当前应失败，因为 60 项尚未执行。

## 仍需完成的原生验收

1. 在已完成的独立浏览器焦点观察上补充真实鼠标/键盘路径和输入传播，验证点击及快捷键使用过程。
2. 验证快捷键录制、中文输入法及原生输入防护暂停。不能为了声称“无失焦”而让文本编辑失效。
3. 核对 Windows 的不激活显示、WM_MOUSEACTIVATE、编辑恢复和窗口重建；当前 Windows 只有交叉编译证据。
4. 使用上述矩阵完成实际共享与输入观察后，再决定哪些能力可作为默认功能，哪些仅能标为实验或不支持。

参考：[Wails 3.1.0 WebviewPanel](https://github.com/wailsapp/wails/blob/v3.1.0/v3/pkg/application/webview_panel_darwin.m) 的 `canBecomeKeyWindow` 返回 YES；[官方面板选项](https://wails.io/features/windows/options/) 提供 NonActivating 和 BecomesKeyOnlyIfNeeded。因此“换到支持 panel 的框架”本身还不能证明被动面板不改变键盘焦点。
