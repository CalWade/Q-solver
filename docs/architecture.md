# Q-solver 架构与开发约定

保留 Go 业务和 Vue 界面，逐步将系统窗口、键盘输入和任务执行拆成独立模块。第一批交付完整键盘防护和自动化开发环境。画面捕获兼容性、焦点保持与键盘事件防护分别验收。

## 分层和依赖方向

新增模块遵循 DDD 分层和依赖倒置。

```text
界面及 Wails 适配器 → 应用层 → 领域层
系统接口及持久化适配器 → 应用层定义的端口
app 负责装配，不在领域层引用 Wails、操作系统或全局配置
```

- `internal/input/domain` 定义按键、快捷键、防护策略和完整按键生命周期。没有系统调用、文件读写或后台线程。
- `internal/input/application` 编排配置、生效状态、编辑暂停和命令分发，通过端口连接外部能力。
- `internal/input/infrastructure` 实现 macOS、Windows 输入接口和键码转换。
- `pkg/shortcut` 保留现有应用入口，作为迁移期适配器，不再维护另一套按键规则。
- `app` 装配服务，将领域命令转交现有截图、解题和窗口服务。
- Vue 负责设置和编辑意图展示，以后端确认的状态为准。

采用小模块逐步迁移。旧模块不因目录调整而批量搬动。每次修改必须给对应行为增加测试。

## 键盘防护的产品规则

1. 总开关及左右独立开关持久保存。Windows 对应 Ctrl，macOS 对应 Command。首次默认关闭，预选左侧。
2. 选中修饰键从按下开始拦截，包括单独按下、组合、重复及释放。助手自己的快捷键动作仍应执行。
3. 未选中侧独立使用时保持正常。两侧同时按下时，受保护侧优先。
4. 被拦截的主键在修饰键先释放后仍须完成自己的生命周期，不能漏出裸字母或孤立释放事件。
5. 快捷键和防护共用已保存配置。仅改变字母键也必须立即对应更新。录制草稿不得提前修改生效规则。
6. 内部文字编辑时暂停相关防护和命令识别。录制快捷键使用独立模式，不触发业务。退出后恢复用户设置。
7. 配置或模式在按键中途变化时，先结束在途按键，再应用新规则。已放行的按下必须正确配对释放。
8. 截图和发送按一次执行一次。滚动和移动允许有意的重复。
9. 界面区分用户设置与实际生效状态。权限缺失、安装失败或监听中断不得显示防护成功。
10. Windows 现有 Alt 快捷键不属于 Ctrl 防护范围。提供明确的防护预设，不静默覆盖用户自定义。

## 验收和边界

单元测试验证规则和状态转换，集成测试验证应用层、配置及驱动端口，E2E 验证真实前端与测试后端的完整流程。系统级实测另列结果，模拟驱动与网页日志不能替代物理键盘、系统事件接收端和实际助手动作的联合验收。

不使用真实会议、公司群、笔试账号或真实模型凭据作为自动化测试前提。开发服务默认只绑定本机，使用隔离配置和可替换的外部服务。

画面保护的系统接口相同不代表所有捕获路径表现相同。非激活面板、私有捕获排除接口和受保护视频层的采用，由独立原型和兼容性记录决定。

## 窗口与截图模块

`internal/window/domain` 区分用户期望、系统确认、本地显示、捕获属性与输入模式；`application` 统一管理窗口注册及截图期间的临时透明状态，系统适配器实现端口。窗口先以隐藏状态创建，再依次应用捕获、输入、鼠标和层级策略，最后显示。关闭/重建必须解除旧注册；不得用新句柄直接覆盖仍生效的注册。

截图使用引用计数租约。新增窗口也继承正在执行的截图状态；最后一个租约释放时应用最新策略。截图、恢复、编码分别处理错误，不能因抓图完成就漏掉恢复失败。`internal/capture` 的来源、图像处理和窗口保护均由端口注入，页面预览与业务截图共用该管道。

Windows 区分排除捕获与旧系统的内容留空；macOS 确认 sharingType 属性设置完成，但不把它描述为所有捕获路径验证成功。macOS 宿主通过下述固定补丁提供被动面板，窗口状态模块仍只确认接口执行结果。

## 请求与同步显示模块

`internal/solve/domain` 定义配置快照、图片身份、对话轮次和事件；应用服务依赖 SettingsSource、Capturer、Generator、Observer 四个端口。一个请求从开始截图起就分配编号；每个进程还有独立会话标识，避免重启后与持久化历史混淆。原来的全局截图缓冲和另一套 TaskCoordinator 已删除。

服务先判断忙碌状态再执行截图，最多保存三张待发送图片。发送时复制全部设置、图片和上下文。取消可以在截图或生成期间发生，旧请求的回调和停止按钮不能影响新请求。只有完整成功的轮次进入最多十轮的模型上下文；清空上下文的版本号阻止在途任务恢复旧历史。

模型适配器只生成结果，不持有 UI、广播对象或可变全局配置。它使用每次请求自己的 Provider；OpenAI 适配器也复制配置。最终内容替换流式草稿，避免二者不同造成主界面与副机不一致。正文和简历不再作为解题调试日志输出。

Observer 接收有序、不可变的事件。当前 UI 适配器投递 Wails 事件，SSE 适配器以单锁更新状态和入队；不得在 Publish 中阻塞等待客户端或重新调用请求服务。慢速接收端的积压会被完整快照替换，连接注册与首次快照原子完成。前端同时检查会话、请求和序号，刷新后从后端快照恢复。

传输 DTO 使用 `app.WindowStatus` 和 `app.WorkflowStatus` 两个不同名称，防止 Wails 2 将两个领域包中的同名 `Status` 合并成错误的 TypeScript 类型。

## 原生面板原型

`cmd/panelprobe` 使用独立 AppKit NSPanel + WKWebView，复用生产窗口应用服务和 macOS 原生适配器。面板在创建时设置 nonactivating 标记，并明确拒绝成为 key/main window；显示操作不请求应用激活。测试结果与局限见 `docs/compatibility/README.md`。

Wails 3.1.0 已有 NSPanel 选项，但其 `WebviewPanel.canBecomeKeyWindow` 返回 YES。这能保持另一个应用的激活状态，却不能直接提供输出面板拒绝键盘焦点的规则。仅升级框架还不够。生产接入需要分别处理被动输出面板和显式编辑窗口，并验证中文输入法、关闭编辑后的焦点恢复及窗口重建。

## 生产宿主与显式编辑

采用 Wails 2.12.0 的固定、最小 Darwin 宿主补丁，保留现有 Go 绑定和 Vue 页面。`patches/` 保存四个文件的差异及前后哈希；`scripts/framework.mjs` 从校验过的模块源创建项目私有副本。Go 的共享模块缓存不被改写；这四个文件的源码或补丁结果不符、已有补丁文件被修改时停止构建。更新上游必须重新审阅补丁、更新哈希并运行原生自检。

窗口在构造时就是 nonactivating NSPanel，默认 `canBecomeKeyWindow == false`，启动不主动激活应用。被动状态下 WebView 允许首击，仍拒绝键盘焦点。设置对话框明确请求编辑后，平台适配器才开启焦点门、保存前台应用并激活编辑窗口。退出编辑关闭焦点门；仅在编辑窗口仍拥有焦点时恢复原应用，避免覆盖用户自行切换的应用。

该窗口实现只属于基础设施层。领域层仍用 `Passive / Editing` 表达意图，不依赖 NSPanel 或 Wails。原生能力缺失会返回失败，不以一次普通 NSWindow 调用冒充被动面板成功。

`cmd/hostprobe` 运行相同的补丁宿主和生产 StateManager，加载本地合成输入框，自动验证启动被动、显式编辑及返回被动。系统焦点与 WebView 焦点异步到达，测试分别等待并确认，不使用固定睡眠推断成功。页面加载失败也会超时退出。此项不等同于物理按键、中文输入法或第三方平台验收。

版本固定的参考：[Wails 3.1.0 面板实现](https://github.com/wailsapp/wails/blob/v3.1.0/v3/pkg/application/webview_panel_darwin.m)、[Wails 面板选项](https://wails.io/features/windows/options/)、[Apple becomesKeyOnlyIfNeeded](https://developer.apple.com/documentation/appkit/nspanel/becomeskeyonlyifneeded)。
